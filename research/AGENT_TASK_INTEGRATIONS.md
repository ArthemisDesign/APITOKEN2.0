## 1. Что мы продаём и зачем это делаем

**apitoken.sale** — доступ к Claude API со скидкой. Технически это **Anthropic-совместимый
эндпоинт**: клиент ставит `base_url = https://api.apitoken.sale`, шлёт обычный Anthropic
Messages API (`POST /v1/messages`), получает обычный ответ. Отличие от Anthropic только в цене
(−60…80% от официальных ставок) и в способе оплаты. Ключи вида `sk-pool-…`.

**Зачем интеграции.** Три механизма, все проверены исследованием:

1. **Дистрибуция без комиссии.** Такие проекты не проводят платежи — пользователь приносит
   СВОЙ ключ. Значит, чтобы ходить через нас, он регистрируется у нас и пополняет баланс.
   Вся маржа наша, посредник не берёт ничего.
2. **Брендовые упоминания** — сильнейший коррелят попадания в ответы ИИ (Ahrefs, 75k брендов:
   корреляция 0.664 против 0.10–0.22 у обратных ссылок). Каждая страница в чужих доках, каждая
   строка `apitoken` в популярном репозитории — это упоминание.
3. **Попадание в обучающие данные и RAG.** Код и доки крупных репозиториев индексируются
   ИИ-краулерами. ChatGPT системно рекомендует популярное (медиана 430 звёзд у рекомендованных
   библиотек против 23.5 у выбранных людьми).

## 2. Жёсткие правила (нарушение = провал задачи)

- **НИКОГДА не описывай механику пула подписок, ротацию, fingerprint, authbot.** Наружу мы —
  «Anthropic-compatible API provider». Только клиентская сторона: base_url, совместимость, цены,
  модели. Причина: с февраля 2026 Anthropic официально запретила subscription-OAuth третьим
  сервисам, а в апреле 2026 проводила массовый DMCA-свип (~8100 репозиториев).
- **Не покупать звёзды, не накручивать активность.** Публично детектится (StarScout, Dagster),
  эффект долгосрочно отрицательный.
- **Не спамить.** Один продуманный PR по правилам проекта лучше десяти шаблонных. Если у проекта
  есть CONTRIBUTING.md — читать и соблюдать. Если провайдеры принимаются только через issue-форму
  (например, `hesreallyhim/awesome-claude-code`) — не слать PR, он будет отклонён автоматикой.
- **Не выдавать себя за третье лицо.** PR идут открыто от бренда, аккаунт `apitokensale-admin`.
- **Не коммитить секреты.** Ключ только в переменной окружения при локальном прогоне.
- **Ничего не мержить и не пушить в чужие ветки.** Только PR из нашего форка.

### ⚠️ ГОТЧА С ТОКЕНОМ (стоила часа работы)

**Fine-grained PAT НЕ МОЖЕТ создавать PR в чужие репозитории** — GitHub даёт таким токенам к
чужим публичным репо только чтение, и «добавить право» в настройках нельзя, такой галочки нет.
Симптом: `GraphQL: Resource not accessible by personal access token (createPullRequest)`.

**Решение:** classic-токен со скоупом `public_repo`
(<https://github.com/settings/tokens/new>). Использовать как `GH_TOKEN=ghp_… gh pr create …`,
чтобы не перезаписывать основной токен в keyring. После работы — отзывать.

## 4. Ошибки, на которых уже споткнулись (не повторять)

1. **`git clone --depth 1` для PR-работы не годится.** Мелкий клон → GitHub отвечает
   `No common ancestor` и PR не создаётся. Клонировать полностью или потом `git fetch --unshallow`.
2. **`git symbolic-ref HEAD refs/heads/<new>` создаёт коммит БЕЗ РОДИТЕЛЯ.** Так получилась
   оторванная история и тот же `No common ancestor`. Правильно — `git checkout -b <branch>`.
   Лечение, если уже случилось: `git fetch --unshallow` → `git reset --soft origin/<base>` →
   повторный `commit` → `git push --force` (в СВОЙ форк, в свою ветку — это безопасно).
3. **Проверять ветку-базу.** У LiteLLM основная ветка не `main`, а `litellm_internal_staging`.
   Смотреть `gh api repos/<owner>/<repo> --jq .default_branch`.
4. **Цены брать из официального прайса, а не из чужого файла.** В LiteLLM зашита промо-цена
   Sonnet 5 ($2/$10), а официальная — $3/$15. Считали скидку от промо и разошлись с собственным
   сайтом. Сверяться с `apps/web/src/lib/learn.ts` и `apitoken.sale/models`.
5. **Прогонять линтеры проекта ДО пуша.** У LiteLLM — `ruff`, `black`, `mypy`. Красный CI сильно
   снижает шанс мержа. Найти конфиг в `pyproject.toml` / `package.json` / `.github/workflows/`.
6. **Сигнатуры переопределяемых методов должны совпадать с базовым классом**, иначе mypy падает.
7. **Мёртвый код в регистрации провайдера.** Мы добавили ветку детекции по адресу, но не внесли
   адрес в перебираемый реестр — ревьюер это поймал (P1). Всегда проверять, что новая ветка
   реально достижима: написать тест, который её вызывает.
8. **Наивная склейка URL.** `base + "/v1/messages"` ломается на `https://host/` и `https://host/v1`
   → `//v1/messages`, `/v1/v1/messages`. Нужен нормализатор, покрытый тестами.
9. **Автоматические ИИ-ревьюеры реагируют не сразу.** Greptile по умолчанию ревьюит ТОЛЬКО
   исходный PR; после новых коммитов он молчит, пока его не позовёшь **комментарием
   `@greptileai`** (кнопка «Re-trigger» ведёт на их сайт и требует аккаунта). GitHub не
   подставляет ботов в автодополнении — писать имя руками.
10. **Первый PR от нового контрибьютора не запускает CI автоматически.** Надпись
    «N workflows awaiting approval» и «pending checks» — это НОРМА, а не ошибка. Ждём мейнтейнера.

## 5. Плейбук на одну цель (повторять для каждой)

1. **Разведка.** Прочитать CONTRIBUTING.md, найти, как проект принимает провайдеров: реестр в
   коде, JSON-файл, страница доков, issue-форма. Найти 1–2 УЖЕ ПРИНЯТЫХ похожих провайдера
   (лучше всего Anthropic-совместимых) и делать строго по их образцу.
2. **Форк + полный клон.** `gh repo fork <repo> --clone=false`, затем обычный `git clone`.
3. **Ветка:** `git checkout -b feat/apitoken-provider` (от актуальной default-ветки upstream).
4. **Реализация по образцу.** Минимальный диф, стиль проекта, никаких лишних рефакторингов.
5. **Тесты.** Написать по образцу соседних провайдеров. Покрыть граничные случаи (слеши в URL,
   отсутствие ключа, достижимость новых веток кода).
6. **Живой прогон** на нашем эндпоинте: обычный запрос, стриминг, tool use. Сохранить вывод —
   он пойдёт в PR как «proof of working» (мейнтейнеры это прямо просят).
7. **Линтеры/типы проекта** — до пуша, в зелёное.
8. **PR** с секциями: Summary / Changes / Tests / Proof of working. Позиционирование —
   «Anthropic-compatible endpoint provider». Ссылка на apitoken.sale — уместная, одна-две.
9. **CLA**, если есть бот. Подписывать под `apitokensale-admin`.
10. **Ревью.** Отвечать по существу, исправлять, пушить, звать ревьюера обратно. Довести до
    «нет блокеров».
11. **Отчёт** владельцу (формат в §8) и переход к следующей цели.
