# Архитектурный аудит claude-api

Снимок после серии работ по устойчивости (2026-07-12). Ниже — что построено, что уже
исправлено, и что **не предусмотрено / можно сделать лучше** (открытые пункты с приоритетами).
Источник: собственный разбор + независимый аудит-агент по всему коду.

## Что построено (эта сессия)

| Коммит | Суть |
|---|---|
| cache-first ядро | `pool::route`: сессии→персоны, пин по кэш-префиксу, спилл, capacity-weighted placement под конвертом конкуррентности |
| per-persona UA | `persona_ua`: флот перестал быть одним отпечатком (пул UA / разброс patch-версии) |
| HTTP/2 keepalive | событийная liveness транспорта вместо idle-таймаута |
| resilience | классификация вины 429/401/5xx, circuit breaker, 429+Retry-After при исчерпании |
| событийный поллер | probe только созревших, сон до due-времени (`select!` + `Notify`), не фикс-тик |
| durability | write-through персист cooling/калибровки — переживают рестарт |
| RAII-гарды | устранены утечки in-flight и резерва баланса при отмене запроса |

## Исправлено по итогам аудита

- **[CRIT] Утечка in-flight + резерва баланса при отмене запроса.** future хендлера дропается на
  `await` → `mark_used(+1)`/`reserve(hold)` не откатывались (ёмкость персоны копилась до рестарта +
  деньги клиента терялись). → **Фикс:** `InflightGuard`/`HoldGuard` (RAII), commit e7f5075.
- **[HIGH] Poison-запрос размыкал глобальный breaker в одиночку** (DoS всем). → **Фикс:** один запрос
  вносит в breaker максимум 1 backend-фейл.
- **[HIGH] 401/403 = 10с cooling** (долбёж мёртвого токена). → **Фикс:** карантин 900с.
- **[HIGH] 5xx студил подписку** за вину апстрима. → **Фикс:** `mark_done` без cooling + breaker.
- **[HIGH] Рестарт стирал cooling** (бан на дни забывался). → **Фикс:** write-through персист.
- **[CRIT] Trust-loopback за реверс-прокси** = аноним-админ. → **Фикс:** `trust_loopback` только при
  bind на loopback; экспонированный bind без ключей отклоняет всё (64702f4).
- **[HIGH] reload не видел смену token/proxy** того же email. → **Фикс:** `replace_subs` всегда (64702f4).
- **[HIGH] Резерв терялся при краше процесса.** → **Фикс:** леджер `reserved_nano` + `reconcile_reservations`
  на старте (64702f4).
- **[HIGH] Нет graceful shutdown.** → **Фикс:** `with_graceful_shutdown(SIGTERM/SIGINT)` — дренаж
  in-flight + финальный флаш (64702f4).
- **[MED] Нет наблюдаемости.** → **Фикс:** `/metrics` (Prometheus): cache-hit rate, in-flight, 429/
  auth/5xx, breaker, cooling. In-flight-gauge ловит регресс утечки слота.
- **Refresh OAuth-токенов** — сознательно НЕ делаем: токены годовые, revoked рефрешем не спасти,
  900с-карантина для редкой ревокации достаточно.

## Раунд 3 (углублённый аудит расчётов/учёта, сверка с авторитетным источником)

**Исправлено (коммиты 108f2ff, 2178eca, 00ab671):**
- **[HIGH — деньги] Fable 5 / Mythos 5 не в прайс-таблице** → считались как Opus 4.8 (недосписание
  вдвое). Сверил ВСЕ ставки с claude-api skill: Opus/Sonnet/Haiku + cache(0.1×/1.25×/2×) + web_search
  верны; добавлена ветка $10/$50.
- **[HIGH — учёт окон] reset-заголовок парсился только как epoch** → если Anthropic шлёт RFC3339,
  вся математика окон (rollover/avail/cooling) молча плывёт. Теперь `reset_ts` принимает ОБА (epoch
  или RFC3339, civil→days без зависимостей); неизвестное → None → fallback, а не кривой epoch.
- **[MED — устойчивость] Breaker размыкался по сырому счёту фейлов** → одна флаки-прокси/poison роняла
  весь пул в 503. Теперь по DISTINCT-подпискам (≥6 РАЗНЫХ email = аутейдж апстрима, а не одна прокси).

**Ещё закрыто в этом заходе (коммиты 90318e6, 10d0c9d, 69d138b, 81b550b, ba14e03):**
- **fair-share** (`KeyLimiter`): кит не набивает флот бёрстом одновременных запросов на ключ (деф 20).
- **systemd** `TimeoutStopSec=600` + hardening: деплой не рубит длинные стримы SIGKILL на 90с.
- **тело как `Bytes`**: clone на ротацию O(1), нет амплификации памяти (до 64MB × N попыток).
- **per-sub прайор по тарифу** (`plan_scale`): Pro/Max5 не переоцениваются как Max20 → нет 429-штормов на старте.
- **SSE-error после 200** детектируется и логируется — сбой посреди стрима больше не тихий.

**Требует ЖИВОГО прогона (не гадаем формат — по принципу «выводить из авторитетного»):**
- util-заголовок: эвристика `v>1.0 ? /100 : v` мисклассифицирует ровно 0–1% (низкий импакт: почти
  пустая подписка). Формат (percent 0–100 vs доля) подтвердить первым живым заголовком, тогда убрать эвристику.
- reset-формат: парсер терпит оба, но какой реально шлёт Anthropic — подтвердить на живой подписке.

## Раунд 2 (два независимых аудитора: корректность расчётов + устойчивость/безопасность)

**Исправлено сразу (коммиты 115f15c, 63ed14a, a073c51):**
- **[HIGH — деньги] Утечка баланса на `count_tokens`/usage-less 200.** `finalize` выходил на
  `is_zero()` до `settle`, hold_guard разоружён → hold не возвращался до рестарта. → резерв
  закрывается всегда (actual=0 = полный возврат).
- **[HIGH — DoS] Один crafted-403 студил весь пул на 900с.** 401/403 больше НЕ студит подписку в
  горячем пути; при повторе на др. подписке → вина запроса → прозрачно отдаём клиенту; дохлые
  токены ловит поллер.
- **[HIGH — утечка] email подписки + сеть-ошибка (прокси host/port) в теле клиенту.** → generic
  клиенту, детали в лог.
- **[HIGH — деньги] `reconcile` возвращал живые резервы при перекрытии деплоя** → двойное
  зачисление. → reconcile только при отсутствии другого живого инстанса (PID-lock + /proc).
- **[MED] `anthropic-ratelimit-*`/org-заголовки утекали клиенту** (раскрытие пула, прыгающий
  лимит). → режутся.
- **[MED] Калибровка искажалась чужим использованием аккаунта** → калибруем только когда наш
  расход объясняет ≥50% Δutil.
- **[MED] Потолок резерва не учитывал web_search/инжект-identity** → добавлены в ceiling.
- **[MED] Нет дедлайна на боевой send()** → `read_timeout(120с)`.
- **[MED] Сбои персиста/reload молча глотались** → логируются.
- **[LOW] Mutex пула не переживал панику** → poison-tolerant; **restore-herd** → polled_ts с разбросом.

**Осталось из раунда 2 (открыто):**
- **[MED res-M2] Breaker путает флаки-прокси с аутейджем апстрима** — сетевой Err кормит глобальный
  breaker так же, как 5xx Anthropic → микро-сбой прокси-провайдера кладёт всех. *Фикс:* отдельный
  учёт «сеть/прокси» vs «5xx апстрима», размыкание по доле, per-proxy health.
- **[MED res-M4] Амплификация памяти тела + нет per-key лимита** — тело в неск. копиях × попытки ×
  неогр. конкуррентность (BODY_LIMIT 64MiB). *Фикс:* Arc/Bytes без клона на попытку, per-key
  concurrency/QPS (fair-share).
- **[LOW] Часы (SystemTime) для cooling/reset** — прыжок вперёд → преждевременный сброс/429. *Фикс:*
  Instant для интервалов.
- **[LOW] Небезопасное по времени сравнение admin-ключей** (timing-oracle, ключи длинные → низко).
- **[LOW] Большой `max_tokens` → большой hold → 402 у малобалансовых** (безопасно, но бьёт UX).

## Открытые находки раунда 1 — что НЕ предусмотрели (по приоритету)

> CRIT/HIGH из первой волны (trust-loopback, reload-по-содержимому, леджер резервов, graceful
> shutdown) и MED-наблюдаемость — **закрыты** (см. раздел выше). Ниже — оставшееся.

### MED

5. **~~Калибровка ломается при использовании аккаунта владельцем.~~ ЗАКРЫТО.** `CALIB_MIN_SHARE=0.5`
   (pool/lib.rs:143): калибруем `cap=Δutil/Δspend` ТОЛЬКО когда наш расход объясняет ≥50% Δutil,
   иначе лишь ре-заякориваемся (чужой трафик/рестарт не искажает ёмкость).
6. **~~`plan` детектится, но не используется.~~ ЗАКРЫТО.** `plan_scale` (pool/lib.rs:284,535):
   прайор ёмкости масштабируется по тарифу (max20=1.0, max5=0.25, pro=0.05) до первой калибровки →
   Pro/Max5 больше не переоцениваются как Max20 → нет 429-штормов на старте.
7. **Multi-instance split-brain.** Всё состояние пула in-memory; два инстанса бьют один аккаунт,
   `pool_state` last-writer-wins, affinity не общая. Деньги безопасны (SQLite reserve/settle атомарны).
   *Направление:* документировать «один serving-инстанс» / общий стор горячего состояния / advisory-lock.
8. **Identical-prefix batch схлопывается на одну персону.** Много запросов с общим префиксом →
   один session_key → одна персона (спилл лишь сверх `MAX_INFLIGHT`). *Направление:* шардировать
   высокочастотные сессии (подмешивать hash%N при занятости дома) / детект batch → load-based.

### LOW

10. **util 1% → 100%.** `v>1.0 ? v/100 : v`: значение `1` (1%) трактуется как 100% → подписка зря
    исключается. *Направление:* фиксировать единицу unified-заголовка, не эвристику.
11. **bindings не персистятся** → холодный prompt-cache после каждого деплоя (осознанный тредофф).
12. **Обрыв стрима после 200** → недосчёт биллинга/калибровки, клиент получает SSE без `message_stop`
    и без явного error-события. *Направление:* инжектить SSE-`error` + метрика обрыва.
13. **Порог breaker зависит от QPS** (абсолют 12/10с), не от доли фейлов. *Направление:* rate-based.
14. **Единый `Mutex` пула** — потолок масштабируемости горячего пути (для скромного QPS ок).
15. **web_search-стоимость не в потолке резерва** → возможен микро-овердрафт. Незначительно.
16. **`reload_loop` (30с) и safety-flush (120с) всё ещё периодичны** — кросс-процессный онбординг
    подписок не событийный. *Направление:* сигнал от CLI/authbot (файл/сокет) вместо опроса БД.

### Не доведено по дизайну (осознанно)

- **Per-persona конверт неполон:** есть потолок конкуррентности (`MAX_INFLIGHT`), но нет
  rate-джиттера и циркадной формы нагрузки (естественность живого юзера) — верхняя планка стелса.
- **Actor-per-persona** не реализован буквально: его цель (событийность, отказ от скана) достигнута
  событийным поллером на одном `Mutex`-состоянии. Отдельные акторы — опциональная будущая структура,
  оправданная в основном при переходе к shared-state / multi-node.

## Раунд 4 — фиксы по 3 независимым аудиторам (учёт/ротация/конкурентность)

Три агента прошли по учёту денег, логике ротации и конкурентности/утечкам. Ядро подтверждено
здоровым (RAII, finalize-идемпотентность, rollover, калибровка, 429-attribution, breaker distinct).
**Исправлено:**
- **[HIGH — деньги] Opus 4.0 (`claude-opus-4-20250514`) недосписывался втрое:** date-id не матчил
  `"opus-4-0"` (после `opus-4-` идёт `2`) → дефолт Opus 4.8 ($25 вместо $75/M). Матчер переписан

- **[HIGH — устойчивость] `breaker.rs` — единственный горячий Mutex НЕ poison-tolerant** (`.unwrap()`).

  `unwrap_or_else(|e| e.into_inner())`, как везде.

- **[MED — устойчивость] `replace_subs` стирал cooling** выпавшей из ростера подписки → вернувшийся

- **[MED — деньги] Резерв `bytes/3` не гарантировал actual ≤ hold** на плотном вводе (CJK/base64) при
  малом `max_tokens`. → `bytes/2` при ставке 2× = покрытие жёсткого предела (токенов всегда ≤ байт).
- **[LOW — деньги] `key_reserve` UPDATE+SELECT не атомарны:** сбой SELECT после коммита → списан
  баланс, но клиенту 402 без HoldGuard = осиротевший резерв. → одно `UPDATE … RETURNING`.
- **[LOW] `plan_scale` unknown = Max20 (оптимистично)** → переоценка ёмкости мислейбл-Pro →
  429-шторм. → консервативный дефолт (как Max5); авторитетно — `sub set-plan`.
- **[LOW] `capacity()` двойной учёт окна при `reset==now`** (`live` брал `now>=reset`, `resets` —
  `reset>=now`). → строгое `>` в `resets`.
- **[LOW] reconcile PID-guard ловился на reuse PID** чужим процессом (пропуск reconcile). → сверяем
  `/proc/{pid}/comm` == наш бинарь и `pid != self`.

Тесты: metering 14, pool 22, registry 8, forward 5 — все зелёные; clippy чист.

## Раунд 5 — закрытие открытых граничных пунктов (2026-07-12)

- **[учёт окон] Третье окно `7d_sonnet` — проверено на ЖИВОМ заголовке: его НЕТ** в unified-ответе
  (только `unified-5h-*` и `unified-7d-*` + `representative-claim`/`fallback-percentage`/`overage-*`).
  Значит наш учёт 5h+7d ПОЛОН для того, что Anthropic реально отдаёт. (Прежняя пометка «пробел
  7d_sonnet» снята — окно не экспонируется в заголовках этого аккаунта.)
- **[ротация — не гадать] 429-атрибуция окна стала АВТОРИТЕТНОЙ.** Anthropic шлёт
  `anthropic-ratelimit-unified-representative-claim` (`five_hour`|`seven_day`) — какое окно связывающее.
  `window_cool` теперь студит до reset ИМЕННО этого окна (если оно ≥0.9), вместо догадки «util≥0.95».
  Retry-After по-прежнему приоритетен; claim — точный фолбэк вместо эвристики. Заголовок захвачен в `Limits`.
- **[безопасность] Timing-safe сравнение админ-ключей** (`ct_eq`, без short-circuit и без внешних
  зависимостей) — устранён timing-oracle на побайтовое угадывание env-ключа.
- **[время — обосновано, НЕ меняем] SystemTime для reset/cooling — корректно by design.** `reset`
  приходит от Anthropic абсолютным wall-clock эпохом; «прошёл ли reset» ОБЯЗАНО сравниваться по
  стенным часам (Instant с чужим эпохом несопоставим). Wall-clock здесь логичен и вытекает из
  авторитетного источника; перевод на Instant сломал бы семантику окон. Скачок системных часов —
  внешняя OS-аномалия вне модели, не «таймаут из воздуха».
- **[веер N>1] Логика распределения зафиксирована тестами:** `route_spreads_sessions_across_fleet`
  (200 сессий → ≥3 из 4 подписок), capacity-placement, конверт конкуррентности, spill-с-сохранением-
  дома. Живьём (метрики route_place по многим email) подтвердится при росте пула — на 1 подписке
  веер физически не наблюдаем, но ветки роутинга (pin/place/spill) уже подтверждены на бою.

Тесты: metering 14, pool 22, forward 10 (+claim/ct_eq), registry 8 — зелёные; clippy чист.

## Раунд 8 — живые тесты на подписке + аудит денежного пути под конкурентностью

**Живые тесты на реальной подписке (Max20):** биллинг ТОЧЕН до нанодоллара на 3 моделях × 2 путях —
не-стрим haiku $0.000231 (=input31×$1/M+output40×$5/M), СТРИМ haiku $0.000227 (usage из SSE), Sonnet
$0.000435 (=$3/$15 по сервёному id). count_tokens не течёт ($5→$5, hold возвращён). Ошибка (плохая
модель)→404 прозрачно без списания. SSE — полный канонический сиквенс + message_stop. util пассивно
читается из заголовка (7d=0.22). «Не на 1 токен ошибки» подтверждено вживую.

**5-й аудитор (денежный путь под конкурентностью):** класс двойного-settle/дрейфа `reserved_nano` —
**ЧИСТ** (главный страх снят): N одновременных на 1 ключ, ротация метерного, обрыв стрима, reconcile —
settle-once/refund-once на КАЖДОЙ ветке. Исправлено:
- **[MED — деньги] Резерв-потолок НЕ был гарантированным верхним пределом charge.** `settle` не
  клампит `charge≤hold`, а `bytes/2` покрывал вход по ставке cache_write_1h лишь до 0.5 ток/байт →
  плотный 1h-cache вход уводил баланс за резерв (на 1 запрос, потом ключ блокируется; тарификация
  ОСТАВАЛАСЬ точной). → `input_est=bytes` (полные байты по cw1h = жёсткий предел, токенов≤байт),
  web_buf 5→20 (мягкий буфер, число поисков заранее неизвестно — честный коммент).
- **[LOW] Нет guard от переполнения i128** при абсурдном client `max_tokens` → кламп `mt≤2M`.
- F3 (reconcile stuck при reuse PID тем же бинарём — деньги застревают, не теряются) и F4 (недосчёт
  хвоста при обрыве стрима — неизбежно, upstream-генерация тоже отменяется) — приняты осознанно.

**Улучшение — наблюдаемость трат в `/metrics`** (по «точно знать сколько клиент тратит»): агрегаты

## Раунд 7 — ЖИВАЯ сквозная валидация веера по N>1 (мок-апстрим)

## Раунд 6 — аудит серверной поверхности (poller/http/config/upstream/panel)

4-й независимый аудитор прошёл по не покрытым ранее файлам. Notify-wakeups, JoinSet, sleep-кламп,
graceful shutdown, panel-XSS, авторизация эндпоинтов — **подтверждены здоровыми**. Исправлено:
- **[CRIT — фингерпринт] persona UA слался ФРАГМЕНТОМ.** `CLAUDE_API_UA` парсился `split(',')`, но
  реальный UA Claude Code содержит запятую (`(external, sdk-cli)`) → дефолт рвался на

  обрезок UA на КАЖДЫЙ запрос (`poll_sub`/`detect_plan`/`/v1/messages`). Битый UA — громче любого
  фингерпринта, мог триггерить блок (обратный эффект фичи). Сервер шёл с дефолтом → слал битый UA
  живьём. → Разделитель списка `|` (в UA не встречается); дефолт-одиночка цел → путь `vary_patch`.
- **[HIGH — аномалия/бан] liveness-поллер пере-пробил COOLING-подписки.** Due-фильтр по `polled_ts`,

## Каталог временных механизмов — каждый обоснован (не «таймаут из воздуха»)

Директива: «не зависеть от ватчдогов/проверок по времени, без таймаутов из воздуха, каждое действие
логично и вытекает из чего-то». Полный перечень тайм-механизмов и почему каждый оправдан:

| Механизм | Значение | Откуда/зачем (авторитетность) |
|---|---|---|
| `reset` окна | от Anthropic | **Авторитетно.** Абсолютный timestamp в заголовке — сброс НЕ поллим, вычисляем локально. |
| 429-cooling | `Retry-After` → `representative-claim` окно → burst | **Авторитетно** (заголовки Anthropic); эвристика только если оба отсутствуют. |
| `BURST_COOL_SECS` 20с | фолбэк | Последний резерв, когда Anthropic НЕ дал ни Retry-After, ни окна-у-потолка = burst по rate (запросов/мин, сбрасывается <60с). Иного авторитетного источника нет; 20с — суб-минутный отбой, не влияет на учёт. |
| h2-keepalive PING 30с/dead 20с | транспорт | **Событийная liveness по протоколу** (не app-таймаут) — ровно замена idle-таймаутам. |
| `read_timeout` 120с | транспорт | Сеть-предохранитель от «подключился и молчит» (застрявший стрим). Не рвёт живые стримы (нет общего request-timeout). |
| `connect_timeout` 30с | транспорт | Ограничение установки TCP/TLS через прокси. Стандарт. |
| `poll_loop` сон | `next_due − now`, clamp[1, 300] | **Событийно:** спим РОВНО до ближайшего due-probe или `poke` (Notify). Не фикс-тик. MAX_SLEEP 300 — верхняя граница переоценки. |
| `LIVENESS_INTERVAL` 300с | probe idle | Токен могут отозвать БЕЗ события — probe неизбежен, но ТОЛЬКО для idle (под трафиком passive-сбор гейтит через `polled_ts`). |
| `reload_loop` 30с | опрос реестра-БД | **Осознанный тредофф.** Влияет ЛИШЬ на onboarding-латентность новой подписки (≤30с), НЕ на учёт/ротацию/аномальность. Событийная замена рискованна: file-watch по WAL-БД самотриггерится на наших же записях `pool_state`; SIGHUP от CLI по PID из лока может убить чужой процесс при reuse PID. Риск > выгоды. `poke` probe-поллера при смене состава — уже событийный. |
| `PERSIST_DEBOUNCE`/`SAFETY` | debounce + backstop | Персист — по СОБЫТИЮ cooling (`on_change`→Notify); safety-flush ловит калибровку (она не event-poke'ит, слишком частая). |
| breaker `WINDOW` 10 / `COOLDOWN` 15 | circuit breaker | Аутейдж апстрима: короткий отбой + probe восстановления. Полу-открытие по времени присуще паттерну (иначе каждый запрос долбит мёртвый апстрим). |
| `AFFINITY_TTL` 3600с | session→home | **Выведено из prompt-cache TTL Anthropic (1ч)** — держим сессию на доме ровно пока тёплый кэш. |
| SQLite `busy_timeout` 5000мс | WAL-контеншн | Стандарт для конкурентных писателей. |

Вывод: тайм-механизмов «из воздуха», влияющих на КОРРЕКТНОСТЬ/учёт/аномальность, нет. Горячий путь
(учёт окон, ротация) полностью событийный/авторитетный; оставшиеся тайм-константы — транспортные
предохранители и onboarding-латентность, не влияющие на «сколько доступно/потрачено».
