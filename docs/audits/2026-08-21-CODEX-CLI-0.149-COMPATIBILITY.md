# Аудит совместимости GPT/Codex-контура с Codex CLI 0.149.0

- **Дата среза:** 2026-08-21
- **Ревизия проекта:** `fe0fb259674d0c25c29e6068a66e6815a0366c59` (`origin/master` на момент начала аудита)
- **Ревизия клиента:** tag [`rust-v0.149.0`](https://github.com/openai/codex/releases/tag/rust-v0.149.0), commit [`758ef40f50c1a458425c7cfbf1eb12cbc07af0b0`](https://github.com/openai/codex/commit/758ef40f50c1a458425c7cfbf1eb12cbc07af0b0)
- **Сравнение клиента:** [`rust-v0.148.0...rust-v0.149.0`](https://github.com/openai/codex/compare/rust-v0.148.0...rust-v0.149.0)
- **Область:** рекомендуемый named custom provider по HTTP/SSE и отдельная внутренняя граница gateway→ChatGPT subscription backend

## Резюме

Текущий GPT-контур **совместим с Codex CLI 0.149.0 для базовых HTTP/SSE turns через документированный custom provider**:

```toml
model_provider = "apitoken"

[model_providers.apitoken]
name = "apiToken.sale"
base_url = "https://router.apitoken.sale/v1"
env_key = "APITOKEN_API_KEY"
wire_api = "responses"
```

0.149 почти не меняет основной Responses wire относительно 0.148. Tagged files основного request/SSE/WS/metadata/endpoint contract не изменились. Парный ephemeral probe реальных npm-пакетов `@openai/codex@0.148.0` и `@openai/codex@0.149.0` показал одинаковые:

- `POST /v1/responses`;
- explicit Bearer auth из `env_key`;
- `store:false`, `stream:true`;
- Responses Lite через `input[].additional_tools`;
- namespaces `functions` и `collaboration`;
- `parallel_tool_calls:false`;
- `reasoning:{effort:"low",context:"all_turns"}`;
- набор ключей `client_metadata`;
- успешное принятие synthetic Responses SSE lifecycle.

Новый 0.149 custom-provider auth hardening нам помогает: клиент больше не подмешивает ambient ChatGPT/OpenAI auth в произвольный provider. Наш профиль уже задаёт явный `env_key`, поэтому Bearer продолжает отправляться корректно.

Полную production-совместимость 0.149 пока заявлять нельзя. Основной wire совместим, но остаются correctness и acceptance gaps:

- **P2, новый source-level gap:** official MCP normalization теперь ограничивает полный canonical model-visible name 128 bytes, а gateway сохраняет отдельный namespace bound 64; stock 0.149 runtime mismatch не воспроизведён, и official dynamic-tool API тоже сохраняет namespace max 64;
- **P1 internal:** gateway→ChatGPT mapping не распознаёт `misalignment_policy_violation`; HTTP 403 может ошибочно запустить auth refresh/profile rotation;
- **P2 correctness risk:** `response.completed` без terminal usage может вернуть success с default-zero usage accounting; exact free settlement не доказан integration test;
- **P2 acceptance gap:** harness не pin-ит exact 0.149 и не имеет отдельного `gpt-5.6-sol` Responses Lite case;
- **P2:** public request и response говорят `parallel_tool_calls:false`, но internal subscription transport принудительно ставит `true`;
- **P3 intentional fidelity gap:** `reasoning.context` и caller-owned `client_metadata` не проходят через adapter;
- **P3 catalog capability gap:** 0.149 различает current `context_window=272000` и configurable `max_context_window=872000`, а gateway сохраняет только current guarantee;
- managed residency — conditional internal deployment risk, а не defect обычного unmanaged profile;
- Responses WebSocket и `/responses/compact` остаются optional capabilities, а не blockers рекомендуемого профиля;
- internal first-party identity остаётся pinned на `0.146.0`; это ограничение доказательств, а не самостоятельный public 0.149 defect.

| Область | Вердикт |
|---|---|
| Базовый `codex exec` 0.149 через named env-key provider | **Совместим на локальной HTTP/SSE границе** |
| Основной Responses request/SSE wire 0.148→0.149 | **Без значимого delta; совместим** |
| Custom-provider auth isolation 0.149 | **Совместим; явный `env_key` — правильный контракт** |
| Responses Lite standard namespaces | **Совместим** |
| MCP canonical-name limit 128 vs namespace 64 | **Source-level gap; stock runtime failure не доказан** |
| Internal policy-error mapping | **Несовместим для SSE и HTTP 400/403** |
| `parallel_tool_calls:false` | **Public false, internal transport true** |
| `max_context_window=872000` | **Configurable ceiling не сохраняется; current 272k остаётся корректным** |
| WebSocket / remote compact | **Опциональные capabilities не реализованы** |
| Exact 0.149 production acceptance | **Не выполнена** |

## 1. Официальный релиз и реальный delta

`rust-v0.149.0` опубликован 2026-08-20 21:04:55 UTC. Release commit — `758ef40f50c1a458425c7cfbf1eb12cbc07af0b0`.

## 2. Проверяемые границы

### 2.1 Public client boundary

```text
Codex CLI 0.149 named provider
  → router.apitoken.sale/v1/responses
  → claude-router
  → fixed OpenAI plane
  → forward::codex public Responses adapter
```

Router сохраняет end-to-end headers, stream upload и stream response. Universal request materialization нужна только для model routing/compatibility rewrite (`crates/router/src/proxy.rs:98-115,158-204,228-258`; `crates/router/src/routing.rs:731-833`). OpenAI plane регистрирует `POST /v1/responses` в `crates/server/src/http.rs:549-588`.

### 2.2 Internal subscription boundary

```text
forward::codex
  → sealed ChatGPT OAuth profile
  → https://chatgpt.com/backend-api/codex/responses
```

Gateway перестраивает request body, headers, identity, history и public SSE. Это adapter, а не byte-for-byte proxy. Internal identity pinned на `0.146.0` (`crates/codex-credential/src/lib.rs:25`; `docs/engine/CODEX_PROVIDER.md:95-97`; `tools/codex-native/probe-live.py:40`). Поэтому public 0.149 compatibility и native ChatGPT 0.149 parity — разные утверждения.

## 3. Подтверждённая совместимость

### C-01 — Basic custom-provider wire не изменился

Следующие tagged files не имеют diff между 0.148 и 0.149:

- `codex-rs/codex-api/src/common.rs`;
- `codex-rs/codex-api/src/endpoint/responses.rs`;
- `codex-rs/codex-api/src/endpoint/responses_websocket.rs`;
- `codex-rs/codex-api/src/sse/responses.rs`;
- `codex-rs/core/src/responses_metadata.rs`;
- `codex-rs/codex-api/src/endpoint/models.rs`;
- `codex-rs/codex-api/src/endpoint/compact.rs`.

Endpoint joining остаётся `<base>/responses`; request shape и event parser не изменились. Наш существующий Responses parser и SSE lifecycle поэтому не требуют отдельного 0.149 adaptation для обычного turn.

### C-02 — Auth hardening 0.149 совместим с нашим профилем

0.149 auth resolver сначала использует provider-owned `env_key`/custom bearer. Если provider не требует OpenAI auth и не имеет command auth, ambient auth больше не добавляется (`codex-rs/model-provider/src/auth.rs:197-218`).

Наш documented profile явно задаёт `env_key`, а `apiToken.sale` key проходит как Bearer. Парный wire-probe подтвердил Authorization на 0.148 и 0.149. Это устраняет возможную утечку `ChatGPT-Account-ID`/ambient bearer на custom base URL и не требует gateway change.

### C-03 — Responses Lite и текущие tool forms принимаются

Официальный `gpt-5.6-sol` продолжает использовать:

- first input item `additional_tools`;
- namespace `functions`;
- namespace `collaboration`;
- function/custom children;
- optional direct `tool_search`.

Gateway извлекает `additional_tools`, принимает function/custom namespaces и direct tool search (`crates/forward/src/codex/api.rs:1563-1809`). Focused tests прошли:

- `codex_cli_0_147_namespaced_custom_tool_is_accepted`;
- `codex_diagnostic_metadata_is_ignored`;
- `additional_tools_match_top_level_tool_leniency`.

Название первого test отражает момент появления формы, но contract остаётся текущим для 0.149.

### C-04 — Models envelope остаётся корректным

Codex ожидает native `{"models":[...]}`. Router/OpenAI plane отвечают Codex-originator клиенту `{"models":[]}`, после чего client сохраняет bundled catalog (`crates/router/src/main.rs:202-258`; `crates/forward/src/codex/api.rs:459-498`). Focused router test `catalog_returns_codex_native_overlay_after_plane_auth` прошёл.

Новый optional `guardian_v2` не нужно синтезировать в empty overlay. Если producer станет non-empty, schema придётся обновить целиком.

### C-05 — Optional capabilities по-прежнему не блокируют профиль

Named provider имеет `supports_websockets:false` по умолчанию. Non-OpenAI provider name получает local compaction, а не `/responses/compact`. Поэтому отсутствие WS/compact routes не ломает рекомендуемый profile. Gap проявится при explicit WS, built-in OpenAI `openai_base_url`, Azure или custom exact `name="OpenAI"`.

## 4. Новые расхождения 0.149

### F-01 — P2 conditional: 128-byte MCP canonical-name delta не покрыт gateway tests

**Официальный 0.149 contract.** `codex-mcp` теперь нормализует **полный canonical model-visible MCP name** до ≤128 bytes. Namespace и tool parts сокращаются/хэшируются, когда composition не помещается (`codex-rs/codex-mcp/src/tools.rs:105-113,225-315`; boundary tests — `codex-rs/codex-mcp/src/connection_manager_tests.rs:1443-1494`). Это не означает, что любой public namespace может иметь 128 bytes: official app-server dynamic-tool validation отдельно сохраняет namespace max 64 (`codex-rs/app-server/src/request_processors/thread_processor.rs:277-323,374-389`).

**Текущая реализация.** Gateway разрешает function/custom child names до 128 и namespace до 64 (`crates/forward/src/codex/api.rs:1615-1618,1727-1733,1793-1796`). Эти отдельные bounds сами по себе совпадают с official dynamic-tool API. Gap находится в отсутствии проверки exact 0.149 MCP normalization/composition и collision/hash outputs на public Responses path.

**Эффект.** Source показывает новый 128-byte canonical boundary, но audit не доказал, что stock Codex CLI 0.149 отправляет gateway namespace 65–128 bytes или что текущий parser отклоняет нормализованный stock request. Поэтому это conditional compatibility/coverage gap, а не установленный runtime blocker.

**Доказательство.** Ephemeral MCP process probe был inconclusive: custom test MCP не попал в first captured request. Live reproduction не заявляется.

**Рекомендация.** Добавить exact stock-client contract fixtures для normalized MCP names на full-name boundaries 64/65/128/129, включая long namespace/tool parts, collision/hash suffix и namespace+child composition. Менять namespace bound следует только по фактическому 0.149 request shape, а не по одному общему canonical limit.

### F-02 — P3: `max_context_window=872000` не сохраняется

0.149 bundled catalog различает:

```json
{"context_window":272000,"max_context_window":872000}
```

для Sol, Terra и Luna (`codex-rs/models-manager/models.json:24-28,138-142,250-254`). Current `context_window` не изменился; новый максимум — configurable ceiling, а не автоматическое разрешение 872k каждому request.

Gateway parser читает только `context_window` и сохраняет его как input guarantee (`crates/forward/src/codex/transport.rs:820-870`). `docs/engine/CODEX_PROVIDER.md:29-38` также определяет public input ceiling только через live `context_window`.

Official manager применяет user `model_context_window` override и ограничивает его через `max_context_window`; это три разные сущности: catalog maximum, configured runtime value и current input guarantee (`codex-rs/models-manager/src/model_info.rs:25-33`; `codex-rs/protocol/src/openai_models.rs:431-485`).

**Эффект.** Базовая работа не ломается, и публиковать 872k как текущую гарантию было бы неправильно. Gateway теряет только metadata о configurable maximum и не может честно предложить opt-in 872k capability. Pricing long-context threshold 272k (`crates/metering/src/codex.rs:174-191`) остаётся отдельным тарифным порогом и не должен автоматически меняться вместе с maximum.

**Рекомендация.** Сначала live-проверить override mechanism и billing/usage выше 272k. Затем добавить отдельное maximum-capability field, не заменяя current input guarantee и не выводя цену из context metadata.

### F-03 — Conditional internal deployment risk: managed residency

Process-wide managed requirement 0.149 принудительно добавляет `x-openai-internal-codex-residency: us` к configured provider request и `/models`, заменяя user-configured copy (`codex-rs/model-provider/src/provider.rs:35-41,215-224`; `codex-rs/model-provider/src/models_endpoint.rs:76-113`). Обычный пользователь не включает эту requirement произвольным request field.

Router передаст header до OpenAI plane. Public adapter не интерпретирует residency, а internal ChatGPT transport строит собственный header set без доказанного residency routing contract (`crates/forward/src/codex/transport.rs:487-533`).

**Эффект.** Public custom-provider compatibility обычного unmanaged profile не ломается. Risk существует только если продукт официально поддерживает managed-residency profile: client-side presence header не доказывает residency внутреннего subscription execution.

**Рекомендация.** Для явно поддерживаемого managed profile fail closed до появления доказанного residency-aware upstream contract либо исключить subscription provider из такого profile. Не копировать internal header вслепую.

### F-04 — P3 conditional acceptance gap: `send_user_message_async`

0.149 добавляет реальный conditional direct function tool. Codex client владеет handler: он эмитит user-visible `AgentMessage` с `delivery:"async"` и возвращает model tool result `{"accepted":true}` (`codex-rs/core/src/tools/handlers/send_user_message_async.rs:21-101`; exposure gate — `codex-rs/core/src/tools/spec_plan.rs:1065-1073`). Bundled GPT-5.6 entries сейчас имеют `experimental_supported_tools:[]`, поэтому stock bundled catalog не активирует tool только из-за upgrade.

Если remote catalog позже включит tool, gateway должен сохранить function declaration, function-call output и next-turn replay. Server-side execution не нужно: tool исполняет Codex client. Но это protocol round-trip, а не только app metadata.

**Рекомендация.** Добавить conditional forward-compat contract test для declaration→call→result→replay. Не рекламировать tool от gateway и не выполнять его server-side.

## 5. Сохранившиеся расхождения 0.148, значимые для 0.149

### F-05 — P1 internal / P2 public adapter: `misalignment_policy_violation`

Official 0.149 сохраняет typed mapping SSE и HTTP 400/403 и теперь явно останавливает TUI chat после такой ошибки (`openai/codex#39261`). Public custom-provider adapter всё равно возвращает OpenAI-shaped failure; критическая часть находится на internal gateway→ChatGPT subscription boundary, где wrong blame может менять refresh/rotation.

Internal gateway mapper:

- SSE exact code превращает в `codexErrorInfo:null`, затем generic protocol error/public 503 (`crates/forward/src/codex/transport.rs:1138-1151,1363-1386`; `crates/forward/src/codex/runner.rs:738-766,805-831`; `crates/forward/src/codex/api.rs:183-230`);
- HTTP 400 становится generic `BadRequest`;
- HTTP 403 становится `AuthenticationRequired` и может вызвать token refresh/profile rotation (`crates/forward/src/codex/transport.rs:873-909`).

**Рекомендация.** Ввести typed terminal policy error для SSE и HTTP 400/403. Она не должна запускать auth refresh, account quarantine или profile rotation.

### F-06 — P2 correctness risk: successful terminal без authoritative usage

`response.completed` без usage всё ещё эмитит `turn/completed`; runner может вернуть success с default-zero usage accounting (`crates/forward/src/codex/transport.rs:1341-1361`; `crates/forward/src/codex/runner.rs:624-629,712-781`). Source не доказывает exact free settlement во всех billing paths; для этого нужен integration regression с authority.

**Эффект.** Публичный success возможен без authoritative terminal usage, с риском underbilling/default-zero settlement.

**Рекомендация.** Fail closed либо применить отдельно утверждённую unknown-usage settlement policy. Добавить exact billing integration test до повышения severity до P1.

### F-07 — P2: public false, internal subscription transport true

0.149 Sol Responses Lite по-прежнему отправляет false. Public parser принимает false, public response отражает false, но internal body всегда ставит true (`crates/forward/src/codex/api.rs:1318-1320,2454-2457`; `crates/forward/src/codex/runner.rs:251-264`). Комментарий в коде описывает это как intentional degradation, но requested execution semantics всё равно не сохраняются.

**Рекомендация.** Передавать false, если live backend принимает. Иначе вернуть явную local error/degradation contract, а не молча инвертировать execution semantics.

### F-08 — P3: `reasoning.context` и caller metadata отбрасываются

`reasoning.context:"all_turns"` игнорируется; upstream получает только effort/summary. Caller-owned `client_metadata` принимается, но заменяется gateway-owned installation/session/thread/turn/window metadata (`crates/forward/src/codex/api.rs:1282-1287,1445-1453`; `crates/forward/src/codex/runner.rs:271-280`; `crates/forward/src/codex/transport.rs:452-485`).

Это intentional adapter behavior, не basic HTTP blocker, но full native fidelity отсутствует.

### F-09 — P2 acceptance gap: exact 0.149 не закреплён

`tests/router_harness_live_matrix.sh`:

- проверяет наличие произвольно установленного `codex`;
- запускает этот бинарник без version pin;
- default model — `openai/gpt-5.4`, не Responses Lite Sol;
- evidence proxy смотрит только top-level tools (`tests/router_harness_evidence_proxy.py:273-344`).

**Эффект.** Matrix не доказывает exact 0.149, Sol `additional_tools`, `parallel_tool_calls`, `reasoning.context`, caller metadata, 128-byte MCP boundary или terminal usage.

**Рекомендация.** Добавить exact-version client runner и отдельные Sol standard/fast/tool-boundary cases. Evidence должен bounded фиксировать additional tools/namespaces, accepted controls и terminal usage без prompt/tool arguments/secrets.

### F-10 — Ограничение доказательств: internal identity остаётся 0.146

Compiled pin и private live probe всё ещё `0.146.0`. Не нужно менять только строку версии. 0.149 native identity требует controlled live proof headers/body/SSE/models/usage/policy errors/OAuth refresh, после чего pin меняется вместе с implementation и tests.

## 6. Auth/OAuth delta 0.149 и наша реализация

### Custom-provider ambient auth

Совместимо. Наш recommended profile имеет explicit env key. Никаких изменений gateway не требуется.

### Official `invalid_grant` permanence

Official 0.149 читает error body и делает `400 {"error":"invalid_grant"}` permanent без следующего HTTP refresh (`codex-rs/login/src/auth/manager.rs:1560-1603`). Наш transport body не читает: любой refresh 400/401/403 становится `AuthenticationRequired`. Затем profile runtime `CodexHome::refresh_locked`, а не public caller, reload-ит encrypted envelope с диска и повторяет только если peer опубликовал другое refresh material (`crates/forward/src/codex/transport.rs:729-771`; `crates/forward/src/codex/mod.rs:803-837`; `docs/engine/CODEX_PROVIDER.md:78-86`).

Это не public client→provider incompatibility. Поведение намеренно учитывает blue-green envelope winner, которого нет в single-process official client. Но mapper не проверяет exact code, поэтому unrelated 400 получает ту же reload policy. Это pre-existing P3 internal precision gap, а не новый 0.149 blocker.

### Provider-owned recovery / Bedrock

Это capability самого Codex для built-in Bedrock. Наш OpenAI subscription plane не является Bedrock provider и не обязан реализовывать `aws.auth_refresh`.

### Парный ephemeral wire-probe

Реальные npm clients 0.148.0 и 0.149.0 запускались с одинаковыми:

- ephemeral `CODEX_HOME` и workdir;
- named `env_key` provider;
- loopback mock `/v1/responses`;
- placeholder secret;
- synthetic terminal SSE с integer usage;
- без live subscription и платного запроса.

Оба завершились exit 0, а `npx … --version` отдельно вернул exact `codex-cli 0.149.0`. Package resolution использовал npm package version, но binary digest и sanitized capture artifact в репозитории не сохранены. Credentials в выводе сравнения были redacted. Поэтому probe — operator evidence request construction и basic synthetic SSE acceptance, а не строго воспроизводимый production artifact. Он не доказывает provider generation, Fast, MCP execution, long context, policy errors или settlement.

Отдельный custom MCP stdio probe был inconclusive: MCP tool не появился в first captured request. Поэтому F-01 основан на exact official/project source bounds, а не заявлен как live reproduction.

### Project tests

Успешно:

- `cargo test -p forward codex_cli_0_147_namespaced_custom_tool_is_accepted`;

Существующие compile warnings не относятся к аудиту и не изменялись.

### Не выполнялось

- live ChatGPT subscription request;
- платный production harness matrix;
- WebSocket/remote compaction live probe;
- >272k context request;
- real MCP execution through production gateway;
- OAuth family rotation;
- deployment или runtime change.

## 8. Рекомендуемый план перехода baseline 0.146→0.149

### Этап A — исправить correctness до bump

1. Зафиксировать stock 0.149 MCP canonical-name fixtures и только по ним решить namespace/composition bounds.
2. Добавить typed `misalignment_policy_violation` для SSE и HTTP 400/403 без refresh/rotation.
3. Требовать authoritative usage на successful terminal или утвердить unknown-usage policy.
4. Сохранить `parallel_tool_calls:false` либо явно отклонять unsupported semantic.
5. Принять отдельное решение по `reasoning.context` и bounded caller metadata.

### Этап B — сделать acceptance точным

1. Pin exact `@openai/codex@0.149.0` или verified binary digest.
2. Добавить Sol Responses Lite standard/fast cases.
3. Добавить MCP full canonical-name 64/65/128/129 fixtures и отдельные official namespace-64 cases.
4. Добавить evidence для controls и nonzero terminal usage.
5. Не включать WS и remote compact в базовый acceptance.

### Этап C — controlled native wire proof

1. Обновить private probe runner для сравнения 0.146 и 0.149 identity.
2. На throwaway profile проверить HTTP headers/body, models query, SSE, Standard/Fast, usage, policy errors и OAuth winner reload.
3. Проверить current 272k и отдельно opt-in >272k только с утверждённым micro-budget.
4. Зафиксировать evidence в новом append-only разделе `research/CODEX_NATIVE_WIRE.md`.

### Этап D — честный pin bump

Только после GREEN этапов A–C обновить одним reviewed change:

- `CODEX_CLI_VERSION`;
- UA/version/models query identity;
- implementation/tests/docs/config example;
- harness baseline.

WebSocket, remote compaction и managed residency routing остаются отдельными capability projects.

## 9. Финальный вердикт

**Codex CLI 0.149.0 можно использовать сейчас через текущий named custom-provider profile для обычных HTTP/SSE turns.** Delta основного Responses wire отсутствует, explicit env-key auth работает, а текущие Responses Lite формы принимаются.

**Простой internal pin bump `0.146.0 → 0.149.0` сейчас преждевременен.** Перед ним нужно зафиксировать exact 0.149 MCP canonical-name fixtures, закрыть internal policy-error mapping, missing-usage policy и parallel-tool semantic, затем выполнить exact-version live acceptance и controlled native wire proof.

0.149 — правильная цель нового baseline. Поддерживать старую identity бесконечными совместимостными ветками невыгодно. Но версия в header должна стать итогом доказанной реализации, а не заменой реализации.
