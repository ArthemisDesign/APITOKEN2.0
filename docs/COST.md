# Учёт токенов и USD-эквивалент

Стоимость хода = токены × **официальные API-цены Anthropic** ($/Mtoken), даже когда ход
идёт на квоте подписки (это метрика «сколько бы стоило по API»). Код — `lib/cost.py`
(порт из движка `tg_agent`).

## Формула

```
usd = ( in·inp + cache_read·rd + cache_write_5m·cw5 + cache_write_1h·cw1 + out·out ) / 1e6
      + web_searches · $0.01
```

## Цены $/Mtoken

| Модель | вход | кэш-запись 5м | кэш-запись 1ч | кэш-чтение | выход |
|---|---|---|---|---|---|
| Sonnet 5 | 3.00 | 3.75 | 6.00 | 0.30 | 15.00 |
| Opus 4.5–4.8 | 5.00 | 6.25 | 10.00 | 0.50 | 25.00 |
| Opus 4.0–4.1 | 15.00 | 18.75 | 30.00 | 1.50 | 75.00 |
| Sonnet 4 | 3.00 | 3.75 | 6.00 | 0.30 | 15.00 |
| Haiku 4.5 | 1.00 | 1.25 | 2.00 | 0.10 | 5.00 |
| Haiku 3.5 | 0.80 | 1.00 | 1.60 | 0.08 | 4.00 |
| (дефолт) | = Opus 4.8 | | | | |

Нет сплита кэш-записи (5м/1ч) в usage → считаем всё как 5м (как в движке). web_search — $0.01/поиск.

## Где учитывается

`bin/claude-api` после каждого хода парсит `usage` из JSON-ответа claude, считает USD
через `cost_from_usage()` и пишет строку в `usage.log`:
```
<ts>  <email>  <model>  in=<..>  out=<..>  cache_r=<..>  cache_w=<..>  usd=<..>
```
Так виден расход по каждой подписке пула.
